# 截取 Framelet 自身窗口

2026-10-27。用户反馈无法截取 Framelet 设置界面。

## 原因与改动

有三处过滤：显示器截图排除当前应用；截图开始前隐藏全部自家普通窗口；窗口列表排除当前进程。因此仅取消其中一处仍无法满足需求。

- 显示器截图不再按应用排除；覆盖层在底图完成后才创建。
- 启动截图时只隐藏启动面板与窗口选择器，保留设置、图片编辑窗口及贴图。恢复逻辑只恢复本次实际隐藏的窗口。
- 窗口列表纳入当前应用的普通窗口。用户明确选择启动面板作为窗口截图目标时，也不会先隐藏该目标。

## 验证

Release 编译、Developer ID 签名和 strict 验证通过。已安装到 `/Applications/Framelet.app`；旧签名包及构建副本可恢复归档在 `work/build-archive/20261027-181900`，不留新的同名启动入口。

真实界面验证：

- 桌面空间中的窗口列表显示「拾影, 拾影设置」和「拾影, 拾影 · Framelet」。
- 选中设置窗口后，预置选区实际显示设置内容，尺寸 1600×1304，工具栏可见，Esc 正常返回。
- 从设置的截图菜单触发区域截图，截图底图仍显示设置窗口，启动面板已隐藏；Esc 正常返回。
- 首次验证时前台为另一应用的全屏空间，设置在其他空间，当前屏幕窗口列表只有该全屏应用。切回普通桌面后完成上述验证；没有将跨空间的不可见窗口宣称为当前屏幕上的截图对象。
