# 截图尺寸标签异常保护

0.3.1 的现场报告显示，拖动截图选区时，`CaptureSelectionChrome.draw` 调用 `NSAttributedString.size`，CoreText `TAttributes::ApplyFont` 内部抛出 `NSInvalidArgumentException`（字典插入 nil），最终以 SIGABRT 退出。这是选区尺寸提示文字，与识别截图内容无关。

未能在独立运行原绘制代码的 1000 次重绘中复现原始字体状态，因此不能把字体名或系统版本认定为已经证实的根因。

0.3.2 改用具名字体，并将尺寸标签的字体创建、测量、绘制全部移入 Objective-C 局部异常边界，异常不穿过 Swift 栈。出现异常后，本次运行停用这个可选标签，边框、手柄、编辑和确认流程继续工作。恢复提示在截图结束后出现一次，菜单可定位本机错误日志；日志记录版本、系统、字体、阶段和堆栈，达到容量阈值后丢弃旧记录，不记录截图内容。

验证命令：

```sh
bash scripts/check-capture-label.sh
bash scripts/swift.sh run FrameletChecks
UNIVERSAL=1 bash scripts/build.sh
```

定向验证调用实际选区 view：正常重绘 1000 次，尺寸标签可见且无错误日志；在文字测量阶段注入现场同类 nil 字典异常后，重绘 1000 次仍存活，图形上下文恢复，边框/手柄绘制与显式隐藏标签一致，错误只记录一次。异常注入由仅用于单独测试编译的宏启用，发行构建不包含主动抛错。

限制：这是对已确认崩溃路径的隔离和规避，未证明 CoreText 内部最初出现 nil 的环境条件已经消失，也不代表应用所有类型的崩溃都可恢复。

本机界面验收：签名 Universal 2 修复版已安装并运行，合成测试图上的选区创建、拖动缩放、移动和打开/取消保存面板均正常；菜单“查看截图错误记录…”可打开无错误时的说明。未通过这次操作复现原始字体异常；异常恢复行为由上述故障注入验证覆盖。
