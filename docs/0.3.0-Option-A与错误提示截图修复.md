# Option+A 与错误提示截图修复

2026-10-27。用户反馈 Option+A 被提示缺少修饰键，报错时启动截图后无法确认选区及显示工具栏。

## 原因与修复

- macOS 的 A 键虚拟键码为 0。旧 `HotKeyCombo.isValidGlobal/isBareKey` 将 `keyCode != 0` 当作有按键的条件，导致 Option+A 被错误拒绝，设置修复也会丢弃它。现在以 Optional.none 表示未配置，按真实键码范围及修饰键键码验证；录制器共享此规则。
- 旧快捷键错误提示调用 `NSAlert.runModal()`。系统级快捷键仍能进入截图，模态事件循环却可能阻挡覆盖层交互。改为快捷键页内提示，错误时保留原绑定，成功重绑清除提示，不创建模态窗口。
- 预选窗口阶段原来 Enter 无动作，只有单击能确认。现在单击或 Enter 均进入编辑状态并展开工具栏；下一次 Enter 才执行完成动作。提示文案同步更新。

## 回归证据

- 在旧安装版真实点击区域快捷键框、按 Option+A，复现「全局快捷键需要包含 Command、Control 或 Option」弹窗。
- 新增 `optionAHotKey` 调用生产校验和编码/修复链。修复前 FrameletChecks 失败：`Option+A must be valid: macOS A has virtual key code zero`；修复后 31 项通过，包括裸 A 工具键、越界键码拒绝、Option+A 编码及修复保留。
- Release、Developer ID 签名和 strict 验证通过。更新唯一安装入口 `/Applications/Framelet.app`；备份在 `work/build-archive/20261027-193014`。
- 新版真实录制 Option+A 无报错，菜单显示「区域截图 ⌥A」。读取应用偏好仅检查该项，保存内容为 `keyCode=0, modifiers=2048`。
- 故意录制无修饰键 B，出现页内错误提示，Option+A 保持；随后从区域截图菜单进入，真实底图包含该提示。按 Enter 展开完整工具栏，点击「复制并退出」后返回设置，覆盖层关闭。
- 再次录制 Option+A 清除验收提示，保留用户要求的组合。截图证据保留在本机 `work/shortcut-acceptance/`，不提交桌面内容。

限制：本轮没有通过自动化验证物理键盘的全局 Carbon 触发；菜单进入截图与全局触发共用同一截图调用链。未声称修复了其他所有类型的系统模态面板。工作区原有图标/工具栏 UI 改动保持未提交，本轮提交只包含对应修复；验收构建包含当时工作区 UI。
