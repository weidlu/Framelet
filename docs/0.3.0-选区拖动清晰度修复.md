# 选区拖动清晰度修复

2026-10-27。用户反馈拖动截图选区像戴了老花镜。本轮按用户修正，仅修复清晰度；没有修改输入法或文字焦点策略。

## 已确认根因

原 `CaptureCanvasView` 的 frame 跟随选区移动/缩放，每次绘制还将 `renderCropped` 生成的图片拉伸到画布 bounds。小数像素选区经 integral 裁剪后，原代码又挤压到小数宽高的位图，再插值绘制，导致截图文字重采样。

新增 `fractionalCropPreservesPixels`，使用一像素黑白细线，调用真实 `Imaging.renderCropped`。修复前运行 `bash scripts/swift.sh run FrameletChecks` 失败：`cropping resampled a sharp screenshot pixel at x=4`。修复后通过。

## 改动

- 画布固定到完整显示器的 bounds，移动、缩放选区只改裁剪范围，不改变底图几何。
- 预览使用全分辨率、屏幕坐标固定的合成图，取消图片缩放插值。标注改变才失效缓存；选区移动复用缓存，不再逐次裁剪重建图片。
- 导出也从同一全图合成结果直接取整像素裁剪，避免预览和保存走不同的标注路径；马赛克仍在先前合成结果上取样，保持已有遮挡。
- 文字输入框和命中区域按选区约束，坐标使用屏幕画布；尺寸标签采用实际导出像素范围。

## 验证

- 独立检查 28 项通过；包含原有标注锚点、遮挡、马赛克覆盖安全、窗口合成和隔离剪贴板检查。Debug/Release 编译及 Developer ID 签名验证通过。
- `/Applications/Framelet.app` 上真实 ScreenCaptureKit 截图：框选 1200×650，移动后尺寸保持；再拉手柄变为 1400×750，工具栏和选区正常。
- 使用 CUA 截图记录移动前后、缩放前后画面。在屏幕矩形 `(1000,550)-(1250,900)` 与 `(1650,550)-(1900,900)` 中比较，共 175000 像素，在两组比较里均完全一致。比较避开工具自身鼠标高亮、边框和工具栏；此前包括鼠标高亮的比较出现差异，不能算作底图变化。
- 在调整后的选区内粘贴 `Framelet QA`，回车后可见红色文字；Esc 正常退出。此项是文本定位回归，不是中文输入法验收。
- CUA 最初的输入会话出现接管/捕获错误，重建工具连接后完成以上验证。未绕过界面工具模拟鼠标。
