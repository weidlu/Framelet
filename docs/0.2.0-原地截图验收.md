# 0.2.0 原地截图交互

用户确认需要 iShot 一类的选区内操作方式：截图时直接在选区下方出现工具栏，无需先打开独立编辑窗口。本版独立实现该交互，不修改或调用 iShot。

## 改动

- 区域截图拖选后进入原地编辑；全屏和窗口截图也进入同一套悬浮工具栏。
- 工具栏默认在选区下方，底部空间不足时放在上方，全屏选区时限制在屏幕可见范围内。
- 选区内直接绘制箭头、方框、圆圈、画笔、马赛克和遮挡，文字原地输入，回车确认文字。
- 完成或 Enter：合并标注并复制图片，然后退出截图；Esc：取消截图。
- 图钉：关闭截图遮罩并直接生成置顶贴图。
- 保存：直接弹出系统保存面板；取消保存后恢复原选区和工具栏焦点。
- OCR：识别结果在工具栏旁的浮动卡片显示，支持编辑和复制。
- 重新选择：清空当前临时选区和标注，重新拖选。
- 未标注时可移动、拖四角调整选区；已标注后可用指针工具移动整张标注图。
- 从文件打开的图片仍使用独立编辑窗口。

## 验证证据

在 Apple Silicon、macOS 26.6.2 上实际启动有 Developer ID 签名的构建，确认版本为 0.2.0。

| 场景 | 结果 |
| --- | --- |
| 区域拖选 | 1200 × 700、1200 × 660 像素选区，松开后仍是同一截图遮罩窗口，工具栏出现 |
| 全屏截图 | 3024 × 1964 像素，工具栏在屏幕内 |
| 原地绘制方框 | 绘制后撤销按钮由禁用变为可用，无编辑窗口 |
| 原地文字输入 | 选区内出现文本框，回车后文本框消失、标注保留、截图遮罩继续存在 |
| 保存面板 | 从悬浮工具栏直接打开系统保存面板 |
| 取消保存 | 曾发现焦点错误，现已修复；复测回到“截图 · Framelet”及同一工具栏 |
| 图钉贴图 | 直接进入“贴图 · 区域截图”浮动窗口，无付费页面 |
| OCR | 从悬浮工具栏打开浮动识别卡片并得到中英文结果，收起后返回同一工具栏 |
| 完成复制 | 图片写入系统剪贴板成功后关闭截图遮罩；没有调用独立编辑窗口 |
| 构建与签名 | arm64、x86_64 Release 编译，Universal 2 合并，Developer ID + hardened runtime + 时间戳，codesign strict 验证通过 |

独立图像检查共 10 项通过：原有 7 项图像测试，以及工具栏下方定位、底部自动翻转、全屏/窄屏/负坐标屏幕边界定位 3 项。

窗口截图已经接入同一原地操作代码；新版本的窗口选区定位、实际多显示器、窗口跨屏和真实 Intel 机器仍需要扩大验收。用户目前要求的区域截图主流程已实际运行检查。

## 分发与公证

0.2.0 安装包有 Developer ID 签名，但尚未获得 Apple 公证。Apple 账号已确认，新版开发者协议已接受。用户终端的公证配置曾返回 HTTP 401 Invalid credentials，因此本机还没有可用的 Framelet 公证 profile；浏览器登录不替代公证凭据。

终端 App 的 Computer Use 被工具安全策略拒绝。本项目没有绕过该限制或读取浏览器生成的密码。后续需要用户直接在本机终端中使用 App 专用密码完成配置，再对 0.2.0 安装包提交公证，不能沿用旧版 0.1.0 安装包的公证状态。
